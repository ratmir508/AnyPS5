# relinker

## change [Guest exports at address 0 on Linux]

- [Guest exports at address 0 on Linux](../../../core/relinker/elfpatcher/src/linux/LinuxGuestModuleWriter.cpp) - the host loader skips a defined symbol whose value is 0 (`check_match` in glibc's `elf/dl-lookup.c`), and the [ps5-payload-dev SDK](https://github.com/ps5-payload-dev/sdk) links a shared object's code at address 0, so its first function is exported at 0, as in the SDK's `hello_so` sample, written as a `jmp` to it in the segment the module gains; a pointer taken through the symbol differs from one the module computes itself, and a `jmp` 2 GiB or more above address 0 fails to convert. A data or untyped export at address 0 stays unresolvable on Linux, and the [module builder](../../../core/relinker/relinker/src/guest/GuestModuleBuilder.cpp) fails the conversion when a non-weak executable or module import references one; a weak import of one still binds to 0. TLS and `SHN_ABS` exports at address 0 stay exempt, as `check_match` exempts them; Windows and macOS are unchanged.

## change An executable relocation against a symbol the executable defines with `STB_LOCAL` binding or `STV_HIDDEN` or `STV_INTERNAL` visibility fails the conversion

- An executable relocation against a symbol the executable defines with `STB_LOCAL` binding or `STV_HIDDEN` or `STV_INTERNAL` visibility ([pipeline](../../../core/relinker/relinker/src/pipeline/RelinkerPipeline.cpp)) binds to that definition as the gABI defines: slot-shaped `R_X86_64_64` and `R_X86_64_GLOB_DAT` references become `R_X86_64_RELATIVE` relocations, resolved by every output format's existing handling, and one note counts them. `R_X86_64_GLOB_DAT` computes S, so its addend is ignored as for imports; `R_X86_64_64` computes S+A. Other relocation types, reserved sections including `SHN_ABS`, and `R_X86_64_JUMP_SLOT` still fail the conversion: a lazy `.rela.plt` entry cannot carry `R_X86_64_RELATIVE`. No title with such a relocation is known.
