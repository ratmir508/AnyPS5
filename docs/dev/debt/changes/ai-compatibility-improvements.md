# relinker

## change An `R_X86_64_GLOB_DAT` or `R_X86_64_JUMP_SLOT` relocation with a nonzero addend fails the conversion

- An `R_X86_64_GLOB_DAT` or `R_X86_64_JUMP_SLOT` relocation with a nonzero addend binds to S ([pipeline](../../../core/relinker/relinker/src/pipeline/RelinkerPipeline.cpp), [guest image reader](../../../core/relinker/relinker/src/guest/GuestImageReader.cpp)): the pipeline drops the addend from the emitted reference, one note counts the ignored addends of the executable, and the guest image reader zeroes the addend of the copied entry, so every output format computes S. The x86-64 psABI computes both as S, as glibc applies them since [f8587a61892c](https://github.com/bminor/glibc/commit/f8587a61892cbafd98ce599131bf4f103466f084) (2.36); FreeBSD rtld uses S for GLOB_DAT and lazy JUMP_SLOT and S+A for eager JUMP_SLOT, so what the console's loader does with such an addend is still not measured.

## change [Guest exports at address 0 on Linux]

- [Guest exports at address 0 on Linux](../../../core/relinker/elfpatcher/src/linux/LinuxGuestModuleWriter.cpp) - the host loader skips a defined symbol whose value is 0 (`check_match` in glibc's `elf/dl-lookup.c`), and the [ps5-payload-dev SDK](https://github.com/ps5-payload-dev/sdk) links a shared object's code at address 0, so its first function is exported at 0, as in the SDK's `hello_so` sample. Such a function export is written as a `jmp` to it in the segment the module gains, so a pointer to it taken through the symbol differs from one the module computes itself, and two names for it get two `jmp`s at different addresses. A module whose `jmp` would lie 2 GiB or more above address 0 fails to convert. A data or untyped export at address 0 stays unresolvable on Linux, and the [module builder](../../../core/relinker/relinker/src/guest/GuestModuleBuilder.cpp) fails the conversion when a non-weak executable or module import references one, naming the export and the module; a weak import of one still binds to 0. TLS and `SHN_ABS` exports at address 0 stay exempt, as `check_match` exempts them, and the Windows and macOS outputs are unchanged.
